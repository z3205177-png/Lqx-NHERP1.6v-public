# 对话中使用

用户的日常操作只有：上传店铺商品Excel或CSV，并要求核对商家编码。其余由Agent完成；结果在当前对话以可打开或下载的Excel文件交付。

## 首次准备：由Agent执行

1. 按当前Agent平台支持的方式安装或下载[完整项目](https://github.com/z3205177-png/Lqx-NHERP1.6v-public)，保留`SKILL.md`、`scripts/`、`config/`、`references/`、`requirements.txt`及两份ERP的相对目录。仅加载说明文件不等于已取得运行资源。将本Skill设为店铺商品编码核验的可调用能力，使用该平台支持的注册方式；不假定所有Agent共用某个安装目录。
2. 检查能否取得会话上传文件的实际内容、执行Python及返回生成文件。缺少能力时说明具体限制；不要改成让用户拖拽到脚本或自行执行命令的默认流程。
3. 复用可用的Python 3.10及以上和已安装依赖。必要时由Agent在权限允许范围内创建项目虚拟环境，用选定解释器运行`python -m pip install -r requirements.txt`。缺少Python时按所在平台的正常安装和授权机制准备，避免重复安装。首次安装需要依赖源网络，已安装后核验过程无需在线服务。
4. 检查`config/erp_library.json`与登记的两份ERP可读且哈希一致；复用现有确认规则。准备完成后，如用户已上传文件，立即继续核验，而不是仅报告安装成功。

## 每次核验：由Agent执行

从会话附件接口取得本次文件的实际路径。附件只有远程文件标识时，用该平台文件工具下载到本次可访问的工作目录。不要猜测用户电脑路径、用历史样本替代，或要求用户挪动文件到脚本目录。

使用选定解释器，以项目目录为工作目录调用：

```text
python scripts/verify_codes.py --platform-file "本次附件的实际路径.xlsx" --output "本次交付目录/商品编码核验结果.xlsx"
```

命令中的`python`指已经选定的实际解释器，路径由Agent按当前环境传入。输出名称或目录应区分本次任务，避免覆盖此前交付。多个文件可重复提供`--platform-file`；文件名不能识别平台时，基于实际表头和用户提供的信息使用`--platform 快手`或`--platform 天猫`。字段语义仍有歧义时询问用户，不猜映射。

现有入口自动使用固定ERP；商品异常不阻止其他行输出。原始输入只读；运行只生成Excel和旁边“核验依据”目录的JSON。ERP更新和业务关系扩展按固定资料库约定处理。

## 对话交付：完成条件

1. 确认命令成功退出并且本次Excel确实存在、可打开。读取实际生成的“全部结果”“需处理”和旁边核验依据，核对全部输入行数、状态统计、需处理数量、原编码保留及候选来源。沿用现有两表12列，完整候选和来源保存在内部JSON。
2. 使用当前平台的附件返回工具或文件下载链接，将Excel交付到当前会话。若平台要求先把文件放到专用交付目录，由Agent完成复制或上传，并检查文件链接指向实际输出。跨机器的磁盘路径、代码块中的路径和外部工具启动说明不能代替可获取的文件。
3. 回复附带Excel和简短统计，例如“已核验N条，需处理M条，见Excel”。统计必须来自本次实际结果。通常只交付Excel，JSON保留内部；文件交付即结束，不要求用户回传确认、修改平台或再次导出。

技术故障由Agent基于实际错误排查，优先修复依赖、路径、编码或文件返回问题。同一故障经三次有不同依据的修复仍失败时，报告具体阻碍和最小所需协助。没有执行环境、附件内容或文件交付能力时如实说明；只有明确解决能力限制后才能声称交付完成。

## 用户可以这样说

> 请用商品编码核验Skill核对我上传的店铺商品文件。使用项目自带的ERP和已确认规则，由你执行核验，并在当前对话附上可下载的结果Excel。

## 共享范围与限制

公开项目包含运行源码、字段映射、已确认规则及SKU关系、固定库登记、两份ERP和自动化测试。历史平台导出、首轮报告、各版交付、备份、临时文件和本机依赖不上传；维护者本地真实回归脚本继续使用本地历史资料。当前审核引擎为v1.7；本次调整改变Agent使用和交付流程，不改变编码判定或Excel格式。

Skill规定操作方式，不能为纯聊天助手增加Python执行或文件附件能力。各Agent的安装、调用和附件返回接口以实际支持为准，不能由Python测试通过推断所有Agent都已验证。
