# 共享使用

完整目录包含`SKILL.md`、`README.md`、`requirements.txt`、`scripts/`、`config/`、`references/`、`tests/`及两份已登记ERP。日常只需提供平台导出文件。ERP更新和已确认业务关系按固定资料库约定维护。

## 同事首次使用

1. 使用有仓库访问权限的GitHub账号下载或克隆项目，保留目录结构。
2. 安装Python 3.10及以上。在项目根目录运行`python -m pip install -r requirements.txt`。
3. 运行`python scripts/verify_codes.py --platform-file "你的平台商品导出.xlsx" --output "reports/核验结果.xlsx"`。文件名不能识别平台时补`--platform 快手`或`--platform 天猫`。
4. 查看输出Excel的“需处理”，需要时查看“全部结果”；交付即结束。

多店铺可以重复提供`--platform-file`。原始输入不覆盖；核验依据JSON保存在输出旁的“核验依据”目录。首次安装需要访问Python依赖源，已安装依赖后运行核验无需在线服务。

## 通过其他助手使用

助手需能读取完整项目及用户平台文件，并在能安装依赖的Python环境执行脚本、交付生成的Excel。是否支持自动导入Skill，由所用助手的实际功能决定；也可以直接让助手读取`SKILL.md`后执行Python。

可对具备以上能力的助手说：

> 请读取这个项目的SKILL.md，使用已登记的ERP标准库核对我上传的平台商品文件。执行现有Python入口，交付“需处理”和“全部结果”两个工作表。按现有规则判断并保留原编码，异常后列出推测编码或候选，不自动修改平台。

仅能聊天、阅读网页或查看单个说明文件的助手，无法完成独立运行。私有仓库也需要相应账号权限；可先由有权限的同事下载完整项目，再提供到允许处理这些业务资料的运行环境。

## 共享范围

共享目录保留运行源码、字段映射、已确认规则和SKU对应关系、固定库登记、两份ERP及自动化测试。历史平台导出、首轮报告、各版交付、备份、临时工作文件和本机依赖不随本次共享上传。历史真实回归脚本依赖这些本地资料，继续由维护者本地运行。审核逻辑沿用当前v1.7；仓库名称不改变程序版本。
