# 回归验证

`scripts/regress_all.py`供维护者复跑指定样本，不改变商品判定规则。私有配置可参考`config/regression_samples.example.json`，每个样本填写唯一`name`、`platform`、`store`、`files`及`source_kind`。同平台可有多个批次；京东暖贴和京东大蒜算两个样本。相对输入路径以配置文件所在目录为准。`store`须与冻结时一致，避免改变人工关系的适用上下文。

```text
python scripts/regress_all.py --config 本机回归配置.json --output 本次输出目录 --baseline 冻结基线目录 --fail-on-change
```

冻结目录按样本名保存`样本名.xlsx`及`核验依据/样本名.json`。输出目录须与基线分开。程序只读输入，不执行编码推断预处理；已有历史清洗文件须标明来源，不视为原始导出。报告记录输入SHA256以核对范围。

默认`full`比较原编码、状态、目标编码、标题、SKU规格、可见候选、完整候选身份（编码、ERP名称、来源及来源行），以及行数和行序。重复ID逐行保留。核验依据与Excel的行数、ID及展示字段不匹配则报错。比较不涵盖全部诊断文案、候选评分及其他内部JSON字段，不能将零差异称为所有输出字段不变。

只有历史Excel而没有依据JSON时，可显式选`--comparison-scope report`，此时只比较可见字段，不验证第4个及后续候选。报告中保留比较范围。

| 场景 | 退出码及报告 |
|---|---|
| 样本缺失、运行失败、空输出、未知状态，或指定基线不完整 | 2；列明缺口，不能称全量通过 |
| 完成比较且有变化，启用`--fail-on-change` | 1；保留逐字段变化 |
| 完成比较无变化，或未启用变化拦截 | 0；仍需阅读变化明细 |
| 未指定基线 | 0（运行完整时）；`total_changes`为空，明确未比较 |

`--only 样本名`可重复，报告会标注选择范围，不代表全部配置。`coverage_complete`只表示所选样本完成读取，`status_valid`表示状态均可识别，`comparison_complete`表示所选范围的基线比较完整；三者分别判断。私有配置或样本未列入清单，程序无法自动发现，须先核对清单范围。

统计分布和零程序差异均不证明商品判定准确率。冻结程序结果与人工真值分开维护；新增人工口径应留下预期变化，不直接覆盖旧基线。
