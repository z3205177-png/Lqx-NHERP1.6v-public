# Lqx-NHERP1.7v

商品编码核验工具 v1.7。

用户在对话中上传店铺商品Excel或CSV，Agent使用项目中长期保存的ERP组合装和单品库自动核验，在同一对话交付含“需处理”和“全部结果”两表的Excel附件。Python 3.10及以上独立运行，不依赖指定Agent或在线核验服务。

## 日常使用

安装Skill后，用户只需上传店铺商品文件并说“请核对商家编码”。Agent负责取得附件、准备环境、执行核验、检查结果并返回可下载的Excel；用户无需安装依赖、运行命令或把文件拖到脚本上。交付后直接参考Excel核对即可。

## Agent内部执行

以下命令由Agent执行，或供用户明确选择手动运行时参考。首次由Agent选择可用的Python环境并安装依赖：

```text
python -m pip install -r requirements.txt
```

Agent在项目目录用本次会话附件的实际路径核验，输出到可供当前对话交付的目录：

```text
python scripts/verify_codes.py --platform-file "本次附件的实际路径.xlsx" --output "reports/核验结果.xlsx"
```

可重复指定`--platform-file`同时核对多个店铺。文件名无法辨认平台时，可用`--platform 快手`或`--platform 天猫`明确；字段语义有歧义时先核对映射。Agent须读取输出核实行数、原编码、状态及候选，再通过会话附件或有效文件链接交付；本地路径文字不代替文件交付。首次准备和交付故障处理见[共享使用](references/共享使用.md)。

Windows安装兼容说明：仓库通过`.gitattributes`保留ERP CSV原始字节，避免Git自动换行转换使SHA256失配；依赖限定pandas `<4`，汇总结果在兼容的数据类型中处理空值。旧安装若已改变CSV换行，需恢复同一版本原始文件并验证哈希。路径测试按文件身份比较，兼容Windows长短路径；PowerShell编码、日志及Agent技能发现检查见[Windows安装与验证](references/共享使用.md#windows安装与验证)。

交付Excel后流程结束，由用户直接参考交付物核对。不要求回传人工确认，也不把修改平台或再次导出作为使用步骤。

## 长期标准库

默认库登记在`config/erp_library.json`，版本`erp-20261025-v1`。完整文件位于`data/组合装.csv`及`data/单品.csv`，两份共5944行；既有确认规则随配置保留。历史平台样本和首轮报告保留在维护者本地，不是同事运行工具的必要文件。日常不会自动更换ERP；只有用户明确通知更新才登记新版本并保留旧版。维护方法见[固定资料库](references/固定资料库.md)。

固定库文件缺失或内容与登记不一致时，程序明确报错，不自动选择其他版本。迁移时携带整个项目，登记采用相对路径。需临时使用其他ERP时同时指定`--combo-erp`和`--single-erp`；只影响本次运行，不会更新固定库。

## 简版交付

- “需处理”：先列明显规格冲突，同类异常及相同规格集中显示。
- “全部结果”：保留全部SKU及原始顺序，包括通过、异常和空编码。
- 每表12列：平台、商品ID、SKU ID、商品名称、SKU规格、原编码、核验结果、推测编码、问题说明、候选1、候选2、候选3。
- 多候选主推测列留空，候选格同时显示编码和ERP原名称，最多展示3个并注明候选总数。按相同明示规格证据的数量排序；证据相同时并列，不把排序当作正确性确认。
- 完整候选、排序依据、原始平台字段及本次ERP版本自动保存到输出文件旁的`核验依据/文件名.json`，供内部追踪，日常无需查看。

默认导出已使用Python实现，不再需要临时整理脚本。历史详细报告及其输出函数保留，默认交付保持两个表。

## 判定规则

| 情况 | 交付结果 |
|---|---|
| 原编码已收录，没有明确冲突，包括信息不足 | 通过 |
| 非空原编码在ERP中未找到 | ERP未找到 |
| 原编码关联商品与平台有明确规格冲突 | 规格不一致 |
| 原编码为空 | 编码为空 |
| ERP同一编码的记录有明确规格冲突 | 待确认 |

比较数量、品类、单配方/混合装、尺码、颜色、材质、容量、型号、香型和套装组成。名称相似仅作线索，不单独定案。足贴、发热鞋垫、暖手足宝1对=2片；三合一混合装只核总数量，不核配比，继续区分ERP单配方。未知尺码表、单位和组成不擅自扩展。

2026-10-27用户逐行复核另存于`config/sku_audit_reviews.json`，绑定平台、商品ID、SKU ID、标题、SKU内容和关联ERP指纹；不依赖来源文件名或本机绝对路径。明确确认的86条关系只用于对应SKU，原码错误时保留异常并提供已确认目标。15条数量档暂定关系保持待确认，3条手套保留规格冲突；不将4双与5对、女生款与儿童款、9英寸与12寸视为通用等价。相关内容变化需重新确认，原始平台编码及两表12列结构不变。这些记录属于人工判定依据，不代表完整人工真值或准确率。

推测使用当前有效的确认关系或真实ERP规格候选，不猜造编码。排序只影响展示，不改变原审核结论、候选集合和单一候选判断。原编码不覆盖，推测不导入确认映射，原始输入只读。编码和ID作为文字保留前导零，原文不执行公式。

## 验证与限制

```text
python -m unittest discover -s tests -v
```

这是开发验证命令，不是用户日常交付后的步骤。维护者本地还可运行`python scripts/run_real_regression.py`，该脚本依赖历史平台样本及v1.6报告，不随共享版上传。真实回归直接调用“只输入快手、天猫文件”的默认入口，输出v1.7简版和回归记录，验证原值、状态、候选集合、排序、固定库和映射文件不变。旧统计只作历史基线；本地实际结果见`reports/回归验证_v1.7.json`。

快手、天猫有真实样本；其他平台先核对导出字段，不宣称已实测。“通过”包含用户允许的信息不足情况，没有完整人工标准答案，不计算真实商品匹配准确率。
